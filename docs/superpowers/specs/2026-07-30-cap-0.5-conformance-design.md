# Coqui ↔ CAP 0.5.0 conformance — migration design

**Status:** approved forks; pending spec review
**Branch:** `feat/cap-0.5-conformance` (worktree `../coqui-cap-migration`, off local `main`)
**Contract:** Coqui Agent Protocol (CAP) **0.5.0**, `coqui-agent-spec` @ `5dffc63` — read-only.
**Primary input:** `coqui-agent-spec/docs/superpowers/COQUI-IMPACT.md` (the coqui-oriented work breakdown; §0–§E + CORE-1…CORE-59).

This document is the migration spine. It records the verified ground truth, the four resolved
design forks, the material spec-vs-coqui disagreements, and the phase breakdown. Each phase gets
its own implementation plan under `docs/superpowers/plans/`.

---

## 1. Objective & definition of done

Make the coqui PHP runtime (and, minimally, the Flutter client) conform to CAP 0.5.0 such that:

- coqui satisfies **every CORE row** in `conformance/checklist.md` (CORE-1…CORE-59);
- coqui's API can **produce and consume** the golden payloads in `conformance/vectors/{valid,invalid,lenient}/**`;
- the **conformance gate passes** (see §4 — it is a coqui-side PHP suite, since the spec's own
  harness is static and never contacts coqui);
- coqui's own test suite (`composer test` / Pest, `composer analyse` / PHPStan) is green per task;
- `meta.schema_version = 0.5.0`; the identity `profile → persona` rename is complete with **zero
  identity-sense "profile" remaining** and the **capability `profiles[]` sense untouched**;
- the Flutter client works against the conformant API.

**No-legacy rule** (`pre-release-no-legacy-support`, Data.md §6): coqui has no installed base. No
migration shims, no ALTER-chains, no `profile→persona` compatibility aliases. Recreate the store at
`0.5.0`; fail-closed-open on any other stamped version.

**Spec wins:** on any coqui-vs-schema conflict, `schema/*.json` is authoritative. Material
disagreements are recorded in §3 with the resolution.

## 2. Verified ground truth (supersedes COQUI-IMPACT's unverified pointers)

COQUI-IMPACT.md warns that every coqui path it names is a spec-side guess. Verified against the real
tree (2026-07-30):

### Storage (`src/Storage/`, `src/Memory/`, `src/Support/SchemaHelper.php`)
- **No migration framework, no `meta`/`schema_version` marker, not fail-closed.** Per-store
  `CREATE TABLE IF NOT EXISTS` + `SchemaHelper::addColumnIfMissing`. Three SQLite DBs under
  `{workspace}/data/`: `coqui.db` (main, PDO owned by `SessionStorage`, shared with Project/Artifact/
  Notification/AuditLog/Loop/Schedule/SkillLifecycle/RuntimeState/BackgroundTaskRecord stores),
  `memory.db` (`MemoryStore`), `history.db` (`EditHistory`).
- **No JSON-Schema library** in the PHP deps (`composer.json`/`.lock`). Must add one.
- **Recreate-from-empty safe:** no seed rows in any DDL; fixed content is file-based config. No live
  DB in the repo. Loop-definition JSON (`workspace/loops/`, `config/loops/`) and per-session uploaded
  files are on-disk state outside the DBs.
- **Timestamps** already Z-suffixed UTC via `Clock.php` (`gmdate('Y-m-d\TH:i:s\Z')`), **second
  precision** (no fractional, no offset) — RFC-3339-compatible. Must confirm every nullable timestamp
  path also uses it (CORE-59).
- Name mapping coqui→spec: `background_tasks`→`jobs`; `task_events`→`job_events`;
  `session_group_members`→`session_members`; `audit_log`→`audit_records`.
- `sessions.model` is **`TEXT NOT NULL`** (must become nullable). No `project_id`, but
  **`sessions.active_project_id`** (migration-added). Project refs also on `loops.project_id`,
  `artifacts.project_id`, `background_tasks.project_id` (plain TEXT, no SQL FK).
- **`child_runs` table exists** but shaped as an audit row: `id, session_id, parent_iteration,
  agent_role, model NOT NULL, prompt, result, token_count, metadata, created_at`. Spec ChildRun needs
  `parent_session_id`, nullable `parent_turn_id`, `role`, nullable `model`, `status` (enum), split
  `prompt/completion/total_tokens`, `completed_at`.
- **No `loop_definitions` table** — definitions are JSON files; `on_question` is a
  `LoopDefinition` JSON field (`src/Contract/LoopDefinition.php:83`), not a column.
- `artifacts` has dormant dead columns `stage`/`persistent`/`storage_mode`/`canonical_path`.
- **No `version` column** for optimistic concurrency anywhere (only `artifacts.version` = a rewrite
  counter, unused for concurrency).
- `memories.profile_id`, `memory_summary.profile_hash`, `session_group_members.profile_name` are the
  identity-sense columns to rename.

### API (`src/Api/`, `src/Command/ApiCommand.php`)
- Hand-rolled `src/Api/Router.php`, base prefix `/api/v1`; central table in
  `ApiCommand::registerRoutes()`; loop/mcp/audit routes self-register.
- **`/profiles` family exists** (`ConfigHandler`), file-backed, full CRUD; rename to persona is
  currently explicitly *rejected* server-side. **No `/personas`.**
- `src/Api/ApiErrorCode.php` has `profile_session_active`, `credential_not_found`; **lacks**
  `version_conflict`, `content_not_found`. Spec `error.json` enum → **drop** `profile_session_active`
  + `credential_not_found`, **add** `content_not_found` + `version_conflict`.
- Lists return `{<name>:[...], count}`, **none cursor-paginate**. `listRoles`/`listLoopDefinitions`
  must become `{data, next_cursor}` name-sorted.
- **No If-Match / ETag / version anywhere.**
- Discovery: `GET /server/info` exists but exposes none of `profiles[]`/`host_toolkits`/`models`/
  `mcp.transports`. No aggregated InstanceInfo document.
- SSE: three streams (`MessageHandler` turns, `TaskHandler` tasks, `LoopHandler` loops); **frame `id`
  is an INT** (spec requires a string cursor, CORE-52); `Last-Event-ID` **not** honored (only
  `?since_id` on `/tasks/{id}/events`).
- Files: `/sessions/{id}/files`, per-session **file id**, no `content_ref`/`sha256`, no global
  `/content`.
- Budget: `GET /server/budget` (session via query param, not `/sessions/{id}/budget`); prompt:
  `GET /server/prompt`.
- Child-run over HTTP is **read-only** (`GET /sessions/{id}/child-runs`); no spawn op. `GET
  /config/models` exists.

### Runtime (`src/Agent/`, `src/Api/LoopManager.php`, `src/Question/`, `src/Config/RoleResolver.php`, `src/Mcp/`)
- **Model pivot is the ROLE, not the session.** `RoleResolver::resolve(role, profile)` precedence:
  profile-role-file → global-role-file → configured-role-model → profile-model → primary. `AgentRunner`
  re-resolves per turn; `session.model` is a non-authoritative cache; null is **ignored**, not an
  "inherit" sentinel. (Disagreement D2.)
- Loops: `LoopExecutor` (orchestration) + `LoopManager` (ReactPHP timers, 5s tick / 3s reconcile).
  Stages dispatch to `definition->roles[stageIndex]` as isolated background-task sessions under the
  loop work-scope session. **Missing role index ⇒ silent stall** (returns null → "no pending stages"
  → Continue), not blocked. (Disagreement D4.) Prior-stage output **is** threaded (`loop_output`
  artifact + truncated summaries). Circuit-breaker `rework_attempts` **exists** in metadata/config
  (`DEFAULT_MAX_REWORK_ATTEMPTS = 3`), but not as persisted `loops.*` columns.
- Questions: `PolicyQuestionResponder` (loop/bg path, `OnQuestionPolicy::Block|DefaultAnswer`,
  `LoopQuestionBlockNotifier` → loop `blocked`, `LoopQuestionAnswerReopener`), plus
  `SuspendingQuestionResponder` (API child-process block-poll) and `InteractiveQuestionResponder`
  (REPL). The block path + `on_question` are deleted; the latter two stay. (Disagreement D4.)
- Project: first-class (`ProjectStore`, `ProjectToolkit`, `/projects`, `active_project_id`,
  propagated into stages). **Shell root is a single GLOBAL workspace** (`WorkspaceResolver` →
  `OrchestratorAgent` binds `ShellToolkit` to `workspacePath`), not per-session. (Disagreement D3.)
- MCP is **core** (`McpRuntime::fromWorkspace()` in `AgentRunner`/`ApiCommand`); tools namespaced
  `mcp_<server>_<tool>`; config `.workspace/mcp.json`; only the mgmt tool + `/mcp` REPL are optional.
  Largely already aligned — needs InstanceInfo declaration + transports.
- Schedules: `ScheduleManager` (60s tick) + `ScheduleStore` (`scheduled_tasks`); same background-task
  runtime as loops; `dragonmantank/cron-expression` (5-field + `@once`). Columns differ from
  `scheduled-task.json`: `schedule_expression` (not `cron`), no `persona_id` (profile in metadata),
  no `action.kind` discrimination (stores `role`+`prompt`).
- Toolkits: `ToolkitDiscovery` (Composer + PSR-4 scan → `.workspace/toolkits.json`); host tools
  register under their **own** names (e.g. `image_*`), no forced namespacing. `coqui-toolkit-images`
  installed. Declare in `InstanceInfo.host_toolkits` (additive).
- Child agents: `spawn_agent` (`SpawnAgentTool`) runs `ChildAgent` **synchronously in-process**,
  logging one `child_runs` audit row; **no nesting** (children lack the tool). Spec makes this a
  gated Core op with `spawnChildRun` (202), status transitions, events, export.

### Flutter app (`/home/carmelo/Projects/CoquiBot/Apps/coqui-app`)
- One service file `lib/Services/coqui_api_service.dart` (~95 methods, plain `http`, `/api/{v}`
  prefix). **No codegen; hand-written lenient parsers; unknown fields ignored, unknown enums →
  `unknown`.** Already forward-tolerant.
- `/profiles*` heavily used (~746 `profile` identifiers, own page/provider/model/picker). Does **not**
  read `protocol_version`. Consumes SSE (turns/tasks/loops) with null-tolerant getters.
- On `main`, clean, **not** on `feat/discord-redesign`.
- Minimal functional delta: ~8 endpoint strings `/profiles→/personas`, a few JSON keys, name→id
  addressing where the API switches to `persona_id`.

## 3. Material disagreements & resolution (schema wins)

- **D1 — Persona persistence.** Spec Persona is persisted/versioned/id-addressed; coqui profile is
  file-backed by name. **Resolution (confirmed): hybrid.** Files (`soul.md`/`backstory.md`/
  `preferences.json`) stay the authoring source of truth; a DB `personas` index table holds
  `id`/`version`/timestamps + a serialized snapshot, synced from files, served over the API.
  `persona_id` becomes the opaque `Id`. The same hybrid applies to the other file-backed authoring
  objects that the contract now versions — **roles** and **loop-definitions** (persisted rows expose
  `version` for the PUT/If-Match contract, CORE-38) — details settled per-phase.
- **D2 — Model resolution.** Spec precedence is **session(non-null) → role → persona → instance
  default**, `session.model=null ⇒ inherit`. coqui makes the role the pivot and ignores
  `session.model`. **Resolution:** introduce a resolver layer where a non-null `session.model`
  overrides, null falls through to the existing role/persona chain, terminating at the instance
  default. This is a real behavioral change (CORE-15); existing role-first behavior becomes the
  fall-through, not the top.
- **D3 — Project removal.** Spec removes `Project` from the protocol; session carries opaque
  `workspace` inherited by stages/child-runs. **Resolution (confirmed): remove from protocol, keep
  toolkit.** Drop `/projects` routes, `project_id`/`active_project_id` from Core objects; add
  `sessions.workspace`; root files/shell there and inherit into loop stages + child runs.
  `ProjectToolkit` may survive as an internal host convenience only if it maps cleanly onto the
  workspace locator (no Core/wire surface, no protocol object). Exact `ProjectToolkit` disposition
  re-confirmed in the Phase-3 plan.
- **D4 — Loops never block; missing role blocks.** Delete `PolicyQuestionResponder` block path,
  `OnQuestionPolicy`, `LoopQuestionBlockNotifier`, `LoopQuestionAnswerReopener`, and the
  `on_question` definition field (CORE-20). Keep `SuspendingQuestionResponder` +
  `InteractiveQuestionResponder` (interactive Core answer path). Add a hard guard: a stage whose
  role/definition is undefined at dispatch resolves **`blocked` + Critical** (CORE-23), not a stall.

Smaller settled points: coqui timestamps are already UTC-Z (low risk for CORE-3/59); MCP is already
core and namespaced (mostly declaration work); host toolkits already have their own tool names
(declaration only). `child_runs` and `scheduled_tasks` tables exist but need column realignment, not
new stores.

## 4. Conformance gate design (confirmed: PHP suite in coqui)

The spec's `npm test` is static ajv validation of the spec's own artifacts — it proves the *vectors
and schemas* are internally consistent, not that coqui conforms. The acceptance gate is therefore a
**coqui-side PHP conformance suite**, run under `composer test`, gating every task:

1. **Dependency:** add **`opis/json-schema`** (JSON Schema **draft 2020-12** — matches the schemas'
   declared `$schema`; `justinrainbow/json-schema` lacks full 2020-12 support).
2. **Vendored contract snapshot:** copy `schema/*` + `conformance/vectors/**` (+ `checklist.md`,
   `error-coverage.json`) into `tests/conformance/spec/`, pinned to spec `5dffc63`, refreshed by a
   `composer sync-spec` script (hermetic CI; reproducible; no dependency on a sibling checkout at
   test time).
3. **Produce:** for each Core object, coqui's serializer emits a real instance that MUST validate
   against the matching `schema/*.json`.
4. **Consume — reject:** each `vectors/invalid/*.json` is fed to coqui's request validator; it MUST
   reject with the catalog error code the checklist names.
5. **Consume — accept:** each authoring vector (`persona.create`, `session-patch`, `role.put`, …) is
   fed to the create/PUT/PATCH path; it MUST be accepted (or rejected for the documented reason).
6. **Roundtrip:** export → import (`mode=preserve` **and** `mode=remap`) in PHP, asserting FK
   integrity across the Data.md §7.3 graph (mirrors `roundtrip.mjs`).
7. **Behavioral CORE rows** (10, 17, 19, 21, 22, 23, 29, 34, …) as ordinary Pest tests — these are
   unprovable by static validation and are the reason a PHP suite is mandatory regardless.
8. **Secondary check:** CI also runs the spec's own `npm test` to confirm the vendored snapshot's
   vectors/schemas are themselves valid (cheap; catches a bad sync).

A `tests/conformance/CoreChecklistTest.php` maps CORE-1…CORE-59 to concrete assertions; the checklist
starts **red** and turns green phase by phase.

## 5. Store cutover (confirmed: recreate-from-empty)

No data to preserve, no marker, no migration framework → recreate. Add a `meta` table (single row:
`schema_version`) written on init; on open, if a stamp exists and ≠ `0.5.0`, **refuse to write**
(fail-closed-open). Rewrite each store's `createTables()` directly to the 0.5.0 shape and drop the
`addColumnIfMissing` accretion for reshaped tables (no ALTER-chains). Loop-definition JSON stays
file-based (authoring source); uploaded-file bytes fold into the `content` model (no existing bytes
to migrate).

## 6. Phase breakdown

Each phase = one SDD implementation plan under `docs/superpowers/plans/`, executed via
subagent-driven-development (fresh Opus 4.8 implementer per task, Opus 4.8 spec+quality reviewer per
task, whole-branch review per phase). Commit per task; `composer test` + `composer analyse` green per
task; never commit red. The conformance gate (green rows) is the phase exit criterion.

- **Phase 0 — Conformance gate scaffold.** `opis/json-schema` dep; vendored snapshot + `sync-spec`;
  `tests/conformance/` harness (producers/consumers/roundtrip plumbing, initially asserting only the
  vectors-are-valid smoke test); `CoreChecklistTest` skeleton (all rows red/skipped). *Exit:* harness
  runs, spec `npm test` wired as secondary, gate is red-but-wired.
- **Phase 1 — §0 identity rename (D1, rename half).** Rename identity-sense
  `Profile*`→`Persona*` (classes, `ProfileDiscovery/Parser/Preferences`, REPL `ProfileHandler` +
  `/persona[s]`, routes `/profiles→/personas`, DB `memories.profile_id`→`persona_id`,
  `session_group_members.profile_name`→`persona_id`, workspace dir `profiles/→personas/`, tests,
  `docs/PROFILES.md→PERSONAS.md`). **Do not touch** the `toolProfile`/`ToolProfileResolver`/
  `TOOL_PROFILE_*` capability sense, perf `test:profile`/`COQUI_TEST_PROFILE_*`, or
  `LeanDefaultProfilePrecedenceTest`. Add the `personas` DB index table (`id`/`version`/timestamps +
  snapshot) synced from files; persona addressed by opaque id. *Exit:* zero identity-sense "profile";
  capability sense untouched; persona persisted + versioned; CORE-1 producible.
- **Phase 2 — §A storage reshape to 0.5.0.** `meta.schema_version=0.5.0` + fail-closed-open; session
  reshape (`members[]`/`kind`/`status`/`pinned`/`workspace`/nullable `model`/`version`; derive
  status from is_closed/is_archived; members from session_members as persona ids); loop diagnostics
  (`rework_attempts`/`dispatch_state`/`last_dispatch_error`); `turns.actor_persona_id`; `child_runs`
  realignment; `content` table (`content_ref`/`mime_type`/`size`/`sha256`/`created_at`);
  `skills.origin`+`execution`; `scheduled_tasks` column alignment; **delete** Project columns,
  `on_question`, dead artifact columns; `version` on the five mutable objects; timestamp audit.
  Per-object serializers validated against `schema/*.json`. *Exit:* CORE-3, 8, 13, 15, 16, 19, 24,
  25, 26, 27, 28, 33, 34, 42, 59 producible; export types every collection (CORE-14).
- **Phase 3 — §D runtime (D2/D3/D4).** Model precedence resolver (CORE-15); session `workspace`
  inheritance + shell/files re-root per session, inherited by stages + child runs (CORE-19/21);
  missing-role → `blocked`+Critical (CORE-23); loops-never-block — delete block path/`on_question`
  (CORE-20); `artifact_required` profile-gated 422 at loop creation (CORE-22); cascade-stop
  non-terminal loops on session delete (CORE-17). *Exit:* those behavioral rows green.
- **Phase 4 — §B API surface.** Error catalog swap; `{data,next_cursor}` pagination + name-sorted
  roles/loop-defs (CORE-18); If-Match/`expected_version`→409 `version_conflict` on the five mutable
  objects (CORE-10); typed loop-live/verdict/termination payloads (CORE-6/7/8); `listModels`
  (CORE-11); PATCH strictness (CORE-9); authoring-vs-persisted bodies (CORE-37); role/loop-def PUT
  create-vs-update (CORE-38); forward-tolerant responses (CORE-36/39); `InstanceInfo` discovery
  (CORE-30/31/35/46); SSE string ids + `Last-Event-ID`/`?since` replay + typed frames + catalog error
  code (CORE-5/41/51/52); `Content` endpoints + attachments (CORE-42/43/44/45); session PATCH
  (CORE-54); budget breakdown (CORE-55); Idempotency-Key (CORE-53); full error set per op (CORE-40).
- **Phase 5 — §C new ops + profiles.** Child-run ops `spawnChildRun`(202,gated)/`getChildRun`/
  `listChildRuns`/`streamChildRunEvents` + `child_run` SSE channel + export (CORE-29); questions Core
  answer path (`submitTurnAnswer`) + SSE question frames (CORE-48/49) + questions profile;
  artifacts profile (served via `getContent`); mcp profile + transports (CORE-31); schedules profile
  + `action.kind` discrimination + dialect advertisement (CORE-33/50); host toolkits + builtin
  toolkits declared (CORE-30/32); `x-profile` op binding parity (CORE-47); in-process binding parity
  + typed thrown errors (CORE-57/58).
- **Phase 6 — gate green + Flutter delta.** Close remaining CORE rows; all vectors produce/consume;
  roundtrip preserve+remap green. Flutter **wire-boundary-only** delta (own worktree off app `main`,
  never `feat/discord-redesign`): `/profiles→/personas`, changed JSON keys, name→`persona_id`
  addressing; keep internal Dart `profile` naming. Per-phase status reports consolidated.

Sequencing rationale: 0 establishes the gate; 1 renames before the storage reshape so §A is authored
in persona terms; 2 lands the data shape the runtime rules need; 3 makes the behavior match; 4/5 bind
it over HTTP + in-process; 6 proves the whole thing and updates the client last (decoupled from the
live app feature branch).

## 7. Risks & collision traps

- **Rename collisions (Phase 1):** three distinct "profile" senses. Rename ONLY identity. Traps:
  `ToolProfileResolver`/`toolProfile`/`TOOL_PROFILE_*` (~138), perf `test:profile`/
  `COQUI_TEST_PROFILE_*` (~59), `LeanDefaultProfilePrecedenceTest` (tool-profile sense despite the
  name). A blind global sed corrupts all of these. The capability `profiles[]` sense does not yet
  exist in coqui core — when `InstanceInfo` adds it (Phase 4), it uses the spec term and must not
  reuse renamed identity code.
- **Model-precedence inversion (D2)** changes real behavior; loop/schedule/child paths currently
  write `model:''` and rely on role re-resolution — verify none regress when null becomes an explicit
  inherit sentinel.
- **Shell re-root (D3)** changes the ShellToolkit sandbox root from global to per-session workspace;
  audit sandboxing/mount logic and the loop-stage inheritance path carefully (safety-sensitive).
- **Loop-block deletion (D4)** removes an existing operator-escalation feature; confirm no downstream
  REPL/API/app affordance silently breaks (surface, don't paper over).
- **Async child-run op:** coqui runs children synchronously; `spawnChildRun` returns 202 with status
  transitions — decide (Phase 5 plan) whether to keep synchronous-execute-then-report or introduce
  real async, without violating the gated/top-level-only/workspace-inheritance rules.
- **Session reshape** is broad (members/kind/status/pinned/version/workspace) and touches group-
  session logic — high blast radius; strong per-object schema tests are the guardrail.

## 8. Out of scope

- Editing the spec repo's normative files (`schema/*`, `openapi.yaml`, `events.yaml`,
  `operations.yaml`, prose docs) — read-only. coqui-side test glue is fine.
- Renaming the spec **repository** slug (`coqui-agent-spec` stays).
- The app's `feat/discord-redesign` feature work — coordinate around it, never absorb/rebase it.
- Any change to protocol **semantics** — we implement the contract, not revise it.
- Migration shims / back-compat aliases of any kind.
- Full Dart identifier rename in the app (wire-boundary remap only).
