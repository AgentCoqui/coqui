# REPL Slim — Remove the Fullscreen TUI, Keep the Portal — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reduce the Coqui REPL to a conversation-only portal by removing the full-screen TUI layer (the `src/Tui/` framework, the loop dashboard/detail screens, and the toolkit fullscreen bridge), while keeping conversation I/O, `/mods`, `/mcp`, tab completion, and a text-only `/loops`.

**Architecture:** This is roadmap item 5 (Phase 1) of the platform-thinning roadmap. It is a *coordinated removal*, not a feature build. The work proceeds in dependency order: first sever every reference from the **kept** files (`LoopHandler`, `ToolkitReplContext`, `SlashCommandRouter`) so the tree stays green, then delete the now-orphaned bridge + framework files, then update docs. Rich loop monitoring moves to the HTTP API (already exists at `src/Api/Handler/LoopHandler.php`); the REPL `/loops` degrades to its existing text path (list table + `/loops <id>` status snapshot).

**Tech Stack:** PHP 8.4, strict types, `final` classes, Pest (test), PHPStan level 8 (analyse), Symfony Console.

## Global Constraints

- `declare(strict_types=1);` in every PHP file; `final` by default; one class per file; 4-space indent; constructor injection.
- **No `git add -A` / `git add .`.** Stage only the exact paths named in each task's commit step. The working tree carries two intentional unstaged edits that MUST remain unstaged and untouched: `.gitignore` (modified) and `.vscode/settings.json` (deleted).
- Every commit message ends with: `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`
- **Do not weaken the safety model** (catastrophic blacklist, audit logging, sandboxing, approval gates are untouched — none live in the removed files).
- **Do not touch Channels / webhooks** or `/channels` — the brief overrides the spec's sequencing note: Channels still exists as a separate roadmap item, so `/channels` stays exactly as-is.
- Validation gate for every task: `composer test` (Pest) **and** `composer analyse` (PHPStan level 8) both green before committing.
- Branch: `feat/repl-slim`, cut from `feat_lean-default` (PR #146 not yet merged at plan time; recorded here per the brief).
